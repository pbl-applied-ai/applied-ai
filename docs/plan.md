# 숏폼 레시피 서비스 기획안 v0.7

수정일: 2026-10-22 · 팀 검토용
변경: 개발 계획 v0.8에 맞춰 항목별 근거·시각 이동·신뢰도 요약을 MVP 화면에서 제외. 내부 근거 검증과 평가·학습은 유지하고, 검증 가설을 추출 정확도와 확인·수정·저장 사용성으로 정리.
관련 문서: [개발 계획](<dev-plan.md>) · [UX 플로우](ux-flow.md) · [경쟁 서비스 비교](<competitors.md>)

## 서비스 소개

**저장만 해 두던 요리 숏폼을, 믿고 따라 할 수 있는 텍스트 레시피로.**

요리 숏폼 링크를 넣으면 재료·분량·조리 순서를 텍스트 레시피로 만들어 내 레시피북에 저장한다. 같은 기능을 하는 서비스(해먹으리, Flavorish, ReciMe, CookingGuru 등)가 이미 있다. 이들과 기능 개수로 경쟁하지 않는다. 우리는 **근거 없는 분량을 채우지 않고, 확인·수정·저장하기 쉬운 간결한 레시피**에 집중한다.

## 왜 이 자리인가

[경쟁 서비스 비교](<competitors.md>)에서 관찰한 화면에서는 재료·분량별 근거 표시를 확인하지 못했고, 단계와 영상 시각 연결은 해먹으리의 YouTube 레시피에서 확인했다. 표본이 작으므로 모든 서비스에 기능이 없다고 단정하지 않는다. 이 관찰은 조사 결과로 남기되, 근거 표시를 이번 MVP의 차별점으로 삼지 않는다. 우리 가설은 내부 근거 검증으로 잘못된 분량을 줄이고 간결한 확인·수정·저장 흐름을 제공하면 레시피를 저장하기까지의 수정 부담을 줄일 수 있다는 것이다.

Flavorish의 공식 안내에는 소셜 게시물 가져오기와 음성 전사 관련 변경 이력이 있고, ReciMe는 캡션 → 음성 → 원본 사이트 활용을 공식 안내한다. 이를 참고해 우리는 링크 수집·전사·레시피 생성을 분리해 설계한다. 다만 네 서비스 모두 실제 Instagram 영상 주소 확보 방법은 미확인이다. 또한 Flavorish는 원문이 부족하면 요리명·해시태그로 빈 내용을 채운다고 안내한다. 우리는 수집 실패나 근거 부족을 모델 추측으로 숨기지 않는다. 상세 근거와 한계는 [Instagram 구현 조사](<competitors.md#instagram-구현-조사>)를 따른다.

## 차별점

1. **근거로 검증하고, 화면은 간결하게.** 근거 종류·원문·시각은 내부 검증·평가용으로 보관한다. 결과에는 요리명·재료·원문 분량·조리 순서를 보여 주고, 항목별 근거·시각 이동·신뢰도 요약은 제외한다.
2. **모르는 분량을 채우지 않는다.** 원문에서 확인된 "약간"은 그대로 두고, 확인되지 않거나 검토가 필요한 분량은 빈칸으로 둔다. 이는 실제 영상에 분량이 없다는 단정이 아니다. 내부 미확인·검토 필요·충돌 상태는 유지한다.
3. **원문 단위 그대로.** 영상이 "2스푼"이라고 했으면 2스푼으로 둔다. 그램 환산은 하지 않는다.
4. **읽은 범위를 숨기지 않는다.** 캡션만 읽었으면 결과 전체에 한 번 "설명 기반"이라고 안내한다. 항목별 출처는 표시하지 않으며, 확보하지 못한 음성·화면을 분석했다고 표시하지 않는다.
5. **정확도를 숫자로 확인한다.** 고정 평가셋으로 재료 누락·분량 오류·근거 없는 분량을 측정하고 기본 버전과 개선 버전을 비교한다. 별도 비교 세트의 경쟁 서비스 결과도 같은 기준으로 채점한다.
6. **고친 것이 품질로 돌아온다.** 고친 항목은 "직접 입력"으로 표시하고 수정 전/후를 보관한다. 검토를 거쳐 학습 데이터 후보로 쓴다.

## 다른 서비스에서 가져오는 좋은 경험

경쟁 서비스의 장점 중 우리 원칙과 맞는 것은 그대로 가져온다.

| 가져오는 것 | 우리 방식 |
|---|---|
| 원본 영상으로 돌아가기 | 링크로 만든 레시피는 원본 링크를 제공한다. 항목별 시각 이동은 MVP에서 제외 |
| 처리 중에 떠나도 되는 흐름 | 레시피북에 "만드는 중" 카드. 진행 단계는 실제 파이프라인 단계를 보여 준다 |
| 같은 영상은 한 번만 처리 | 같은 영상·추출기 버전의 유효한 성공 결과를 재사용해 비용과 대기 시간을 줄인다 |
| 원본과 내 수정을 나눠 보관 | 추출 결과는 고치지 않고, 내 레시피는 그것을 참조하는 사본. 항목 단위로 되돌리기 가능 |
| 원문과 정리된 수량을 함께 보관 | 화면에는 원문, 정리된 수량은 검증과 평가에만 쓴다 |
| 실패 이유를 구분해 안내 | 일시 오류, 열 수 없는 영상, 요리 영상 아님, 정보 부족을 구분 |
| 외부 재생이 막힌 영상 처리 | 원본 앱으로 보내는 링크로 대체 |
| 수집·전사·생성의 분리 | 플랫폼별 수집 결과를 공통 근거로 바꾼다. 자막이 있으면 재사용하고 필요한 경우에만 확보한 미디어를 전사·OCR 처리 |

## MVP 범위

| 기능 | 결과 |
|---|---|
| 영상 → 텍스트 레시피 | 요리명·재료·원문 분량·조리 순서. 확인되지 않은 분량은 빈칸 |
| 확인·수정 | 사용자가 결과를 고친 뒤 저장. 고친 항목은 "직접 입력"으로 표시 |
| 내 레시피북 | 저장한 레시피 목록·상세·수정·삭제 |
| 지원 입력 | YouTube Shorts 링크, 영상 파일 업로드. Instagram은 수집 검증 후 미지원/캡션 제한 지원/음성·영상 포함 지원 범위를 결정 |

**화면 범위:** 항목별 근거 버튼·원문·출처·시각 이동, 신뢰도 요약, 출처 충돌 표시는 제외한다. 캡션만 사용한 결과의 "설명 기반" 안내는 결과 전체에 한 번 유지한다.

**내부 검증:** 숫자 경계와 재료·분량의 연결을 검증한다. 미확인·검토 필요·충돌은 내부 상태로 보존하고 화면 분량은 비운다. 이 값들을 사용자에게 확인된 분량으로 제시하지 않는다.

MVP를 좁게 유지하는 이유는 추출 품질을 계속 개선하는 데 시간을 쓰기 위해서다. 장보기, AI 질문, 영양 성분, 포크처럼 경쟁 서비스가 이미 잘하는 기능은 따라가지 않는다.

## 사용자 흐름

로그인 → 링크 입력(또는 영상 파일) → 처리 중(떠나도 됨) → 레시피 확인·수정 → 레시피북에 저장 → 레시피북에서 다시 보기.

처리 실패 시 이유에 맞는 다음 행동을 안내한다. 일시 오류는 제한된 재시도, 링크로 가져올 수 없는 영상은 사용 권한이 있는 영상 파일 업로드, 요리 영상이 아니면 다른 영상 안내, 정보가 부족하면 찾은 만큼 보여 주기. 캡션은 있지만 영상 접근에 실패한 경우 전체 실패와 구분해 설명 기반 결과를 안내한다. 화면 상세는 [UX 플로우](ux-flow.md)를 기준으로 후속 반영한다.

## 영상 변환 원칙

- 한국어 요리 숏폼을 대상으로 한다. YouTube Shorts를 먼저 완성하고, Instagram 릴스를 조건부로 추가한다. TikTok은 여유가 있을 때 추가한다.
- URL만 모델에 넘긴 것은 영상 분석으로 보지 않는다. 실제로 확보한 음성·화면 텍스트·설명을 근거로 레시피를 만든다.
- 근거는 출처와 ID가 있는 구간 단위로 보관한다. 자막·음성·화면에서 확보한 시각만 기록하며 설명·캡션에는 시각이 없어도 된다. 모델은 구간 ID만 인용하고 시각은 코드가 계산한다. 시간 정보가 없는 전사에 시각을 추정해 붙이지 않는다.
- 원문 분량을 보존하고, 확인되지 않은 분량은 빈칸으로 둔다. 단위 환산은 하지 않는다.
- 사용자가 고친 내용은 원본 추출 결과와 함께 보관해 품질 개선 데이터로 쓴다. 사용자에게 이 사실을 안내한다.
- 사용자 원본 미디어는 처리·재시도에 필요한 기간만 임시 보관 후 삭제하고 근거 텍스트·메타데이터를 남긴다. 평가·학습용 영상은 별도 보관한다. 정확한 보관 기간·삭제 기준은 #3에서 합의한다. [결정 필요]
- 원작자나 권리자가 삭제를 요청하면 해당 레시피를 내린다.

## Instagram 릴스 (조건부)

Instagram 릴스는 지원 후보로 두되, 실제 수집 가능 범위를 확인한 뒤 결정한다. 경쟁사의 공유 메뉴·oEmbed 재생·AI 분석 안내만으로 원본 영상 수집 방법을 확보했다고 보지 않는다. 이번 조사에서도 수집 업체·다운로더는 미확인이다. 따라서 지금 특정 API나 공급자로 구현하기로 확정하지 않는다.

- **우선순위:** YouTube 링크→저장 흐름을 먼저 완성한다. 기존 YouTube 전용 코드는 플랫폼별 수집기·공통 근거 처리·재생 링크 어댑터로 나눠 확장한다.
- **사전 검증:** 1주차에 최대 2인일로 개발용 공개 릴스 12개의 캡션·미디어 접근·시간 있는 전사 가능성을 다른 날 2회 기록한다. 품질·비용 통과 기준은 실험 전에 합의하고, 10/27에 결과를 보고 지원 범위를 결정한다. 평가셋과 분리하며 상세 방법은 [개발 계획](<dev-plan.md#instagram-수집-검증과-지원-결정>)을 따른다.
- **캡션 제한 지원:** 설명에 충분한 레시피가 있으면 시각 없는 근거로 구조화한다. 영상·음성을 분석한 결과로 표시하지 않는다.
- **음성·영상 포함 지원:** 실제 미디어 접근과 전사/OCR·근거 품질을 검증한 경우에만 추가한다. 시각은 내부 평가에 사용하며 MVP에서는 항목별 시각 이동을 제공하지 않는다.
- **불충분·실패:** 확보한 근거가 부족하면 부분 결과 또는 사용 권한이 있는 영상 파일 업로드를 안내한다. 미디어 URL만 반환받은 상태를 영상 분석 성공으로 세지 않는다.
- **재생:** Instagram은 원본 링크를 제공한다. 근거 원문·시각은 내부에 보관하고 화면에는 표시하지 않는다. 임베드 재생과 분석용 미디어 확보를 구분한다.
- **운영 범위:** 사용자가 넣은 공개 링크 하나만 처리한다. 대량 수집이나 개인 계정 쿠키를 통한 제한 우회는 하지 않는다. 수집·전사 비용과 실패 원인을 기록한다.
- **보류 조건:** 사전 검증이 미달하거나 일정이 밀리면 우선 제외한다. 수집 성공률과 레시피 추출 정확도를 분리해서 평가한다.
- 담당 선생님 면담에서 보류했던 항목이므로 지원 범위·실패 대안을 다시 공유하고 진행한다. [결정 필요]

## 차별화 가설과 검증

가설: 내부 근거 검증으로 근거 없는 분량을 줄이고, 간결한 확인·수정·저장 흐름으로 저장 전 수정 부담을 줄일 수 있다. 화면 근거 표시의 효과는 이번 MVP에서 검증하지 않는다.

- 정답 레시피를 직접 만든 영상 평가셋으로 재료 누락·분량 오류·영상에 없는 분량을 측정한다.
- 같은 평가셋으로 기본 버전과 파인튜닝 버전을 비교해 개선 폭을 숫자로 보여 준다.
- 평가셋 정답에서 재료마다 어느 출처(설명·말소리·화면 글자)로 확인되는지 집계해, 한국 요리 숏폼에서 어떤 근거가 중요한지 확인한다. 이 결과로 음성 인식과 화면 글자 인식 중 어디를 먼저 개선할지 정한다.
- 별도의 비교 세트로 같은 영상을 경쟁 서비스에 넣은 화면 결과를 같은 지표로 채점한다([비교 실험 계획](<competitors.md#비교-실험-계획>)). 작은 표본의 결과를 일반화하지 않는다.
- Instagram은 캡션 확보율·미디어 사용 가능률·전사 시각 확보율을 먼저 기록한다. 레시피 품질은 실제 확보 출처별로 비교하고 시각 없는 출처는 시각 정확도에서 분리한다.
- 지인 3~5명이 영상 저장 → 확인·수정 → 레시피북 흐름을 쓰게 하고, 수정한 항목 수·확인부터 저장까지 걸린 시간·저장 완료 여부를 기록한다. 영상 재확인 횟수는 사용성 참고 지표로만 기록하며, 근거 표시의 효과나 인과적 개선을 입증하는 지표로 해석하지 않는다.

전수빈은 추출 파이프라인·수집 계약·Instagram 사전 검증, 김선규는 데이터·평가·파인튜닝 루프와 레시피북 백엔드, 송유란은 디자인·프론트엔드를 맡는다. 상세 일정과 완료 기준은 [개발 계획](<dev-plan.md>)을 따른다.

## 메모: 보류한 기능

MVP 이후 후보로만 남긴다. 다시 넣을 때는 추출 정확도가 목표치에 도달했는지 먼저 확인한다.

| 기능 | 메모 |
|---|---|
| 냉장고 사진 인식 | 사진 → 재료 후보 → 확인·수정. 이미 비슷한 앱(냉장고 털기, SuperCook 등)이 있어 단독 차별점은 약함 |
| 요리 에이전트(추천·대체) | 저장 레시피 × 내 재료로 추천, 부족 재료 대체안 |
| 내 재료 목록·재고 | 해먹었어요 → 사용량 자동 차감, 유통기한 |
| 단위 환산·양념 비율 | 그램 ↔ 큰술·컵 환산은 영상에 없는 정밀도를 만들 수 있어 원칙과 충돌. 넣는다면 원문과 따로 "참고값"으로만 표시 |
| TikTok 지원 | 임베드에서 시각 이동은 가능. 수집 불안정은 Instagram과 같음. 여유가 있을 때 수집기 추가 |
| 단계별 재료 표시, 요리 모드, 타이머 | 경쟁 서비스에 있는 편의 기능. 차별점과 무관해 후순위 |
| 장보기·커머스 연동, AI 질문, 영양 성분, 포크·공유, 폴더·고급 검색 | 경쟁 서비스가 이미 잘하는 영역. 우선순위 낮음 |
