# 숏폼 레시피 서비스 기획안 v0.4

수정일: 2026-10-19 · 팀 검토용
변경: 담당 선생님 면담 결과 MVP를 "영상 → 텍스트 레시피 → 내 레시피북"으로 축소. 냉장고 인식·요리 에이전트 등은 보류 메모로 이동
관련 문서: [개발 계획](dev-plan.md) · [UX 플로우](ux-flow.md)

## 서비스 소개

**저장만 해 두던 요리 숏폼을, 믿고 따라 할 수 있는 텍스트 레시피로.**

요리 숏폼 링크를 넣으면 재료·분량·조리 순서를 텍스트 레시피로 만들어 내 레시피북에 저장한다. 같은 기능을 하는 서비스(해먹으리, 레시피오 등)가 이미 있으므로 차별점은 **추출 정확도**와 **근거 표시**다. 재료와 분량마다 자막·음성·화면 텍스트·설명 중 어디서 나왔는지를 보여 주고, 확인되지 않은 분량은 지어내지 않는다.

## MVP 범위

| 기능 | 결과 |
|---|---|
| 영상 → 텍스트 레시피 | 요리명·재료·원문 분량·조리 순서·출처, 항목별 근거, 미확인 분량 표시 |
| 확인·수정 | 사용자가 결과를 고친 뒤 저장 |
| 내 레시피북 | 저장한 레시피 목록·상세·수정·삭제 |

MVP를 좁힌 이유는 추출 품질을 계속 개선하는 데 시간을 쓰기 위해서다. 먼저 끝까지 동작하는 흐름을 만들고, 이후에는 정답 데이터와 파인튜닝으로 추출 정확도를 반복해서 올린다.

## 사용자 흐름

링크 입력 → 처리 중 → 레시피 확인(근거·미확인 표시) → 수정 → 레시피북에 저장 → 레시피북에서 다시 보기.

처리 실패 시 이유와 재시도를 안내한다. 링크 수집이 막히는 영상은 사용 권한이 있는 영상 파일 업로드로 대신한다.

## 영상 변환 원칙

- 한국어 요리 숏츠(YouTube Shorts)를 우선 지원한다. 인스타 릴스·틱톡은 보류한다.
- URL만 모델에 넘긴 것은 영상 분석으로 보지 않는다. 실제로 확보한 음성·화면 텍스트·설명을 근거로 레시피를 만든다.
- 원문 분량을 보존하고, 모르는 분량은 "영상에서 확인되지 않음"으로 표시한다.
- 레시피 항목마다 근거 종류와 위치(가능하면 영상 시각)를 남긴다.
- 사용자가 고친 내용은 원본 추출 결과와 함께 보관해 품질 개선 데이터로 쓴다. 사용자에게 이 사실을 안내한다.

## 차별화 가설과 검증

가설: 근거가 붙은 정확한 레시피는 사용자가 영상을 다시 돌려 보지 않고도 따라 할 수 있게 해 준다.

- 정답 레시피를 직접 만든 영상 평가셋으로 재료 누락·분량 오류·근거 없는 분량을 측정한다.
- 같은 평가셋으로 기본 버전과 파인튜닝 버전을 비교해 개선 폭을 숫자로 보여 준다.
- 가능하면 같은 영상을 경쟁 서비스에 넣은 결과와 비교한다. 작은 표본의 결과를 일반화하지 않는다.
- 지인 3~5명이 영상 저장 → 확인·수정 → 레시피북 흐름을 쓰게 하고 수정이 얼마나 필요했는지 기록한다.

## 메모: 보류한 기능

MVP 이후 후보로만 남긴다. 다시 넣을 때는 추출 정확도가 목표치에 도달했는지 먼저 확인한다.

| 기능 | 메모 |
|---|---|
| 냉장고 사진 인식 | 사진 → 재료 후보 → 확인·수정. 이미 비슷한 앱(냉장고 털기, SuperCook 등)이 있어 단독 차별점은 약함 |
| 요리 에이전트(추천·대체) | 저장 레시피 × 내 재료로 추천, 부족 재료 대체안. 재료 매칭은 코드로, 설명·판단은 에이전트로 나누는 구조였음 |
| 내 재료 목록·재고 | 해먹었어요 → 사용량 자동 차감, 유통기한 |
| 단위 환산·양념 비율 | 그램 ↔ 큰술·컵, 간장:설탕 = 2:1 같은 비율 표시. 재료별 밀도표 필요 |
| 인스타 릴스·틱톡 지원 | 수집 정책 확인 필요. 인스타는 타임스탬프 연결이 어려움 |
| 장보기·커머스 연동, 공유, 폴더·고급 검색 | 우선순위 낮음 |
