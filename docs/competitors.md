# 경쟁 서비스 비교 v0.3

수정일: 2026-10-22 · 팀 검토용
변경: 경쟁사 관찰·공식 자료는 유지하고, 우리 대응·검증 방향을 개발 계획 v0.8의 간결한 MVP 화면에 맞춤.
관련 문서: [기획안](<plan.md>) · [개발 계획](<dev-plan.md>) · [UX 플로우](ux-flow.md)

## 이 문서의 기준

- 사용자 화면 관찰과 공식 도움말·정책·변경 이력을 구분한다. 공식 설명은 서비스의 주장이며 실제 처리 성공을 검증했다는 뜻은 아니다.
- 관찰 표본이 작으므로 서비스 전체로 일반화하지 않는다. 서비스 변경에 대비해 발표 전에 다시 확인한다.
- 경쟁 서비스는 일반 사용자로만 사용한다. 내부 API 직접 호출, 이용 제한 우회, 자동화된 대량 제출은 하지 않는다.
- 공개 문서에는 화면 관찰과 공식 설명의 요약·출처만 포함한다. REA 캡처·내려받은 코드·분석 스크립트·내부 구조 메모는 포함하지 않는다.
- 이번 추가 조사에서 로그인 후 Instagram 가져오기·유료 변환은 실행하지 않았다. 실제 영상 수집 방법과 성공률은 미확인이다.

## 서비스별 관찰

### 해먹으리 (Hemogry)

- 앱의 공유 버튼으로 링크를 넘기면 서버에서 만들고, 끝나면 알림을 준다. 처리 중에는 "영상을 보고 있어요 → 재료를 뽑아내고 있어요 → …" 같은 단계 문구가 나온다.
- YouTube 레시피는 단계마다 `00"05`처럼 시각이 붙고, 누르면 위쪽 플레이어가 그 지점으로 이동한다. 단계 아래에 그 단계에서 쓰는 재료와 팁이 나온다.
- Instagram 레시피는 Instagram 임베드로 보여 주며, 단계에 시각이 없는 경우를 관찰했다. "인스타그램 레시피 생성을 잠시 점검하고 있어요" 안내도 관찰했다. 조사 당시 관찰이며 현재 전체 서비스 상태로 일반화하지 않는다.
- 소유자가 외부 재생을 막은 YouTube 영상은 "동영상을 재생할 수 없음"이 뜨고 YouTube로 보내는 버튼만 남는다.
- 재료는 원문 단위(1/4개, 2스푼, 한 줌)로 보여 준다. 다만 "약간", "적당량"이 영상에서 나온 말인지 알 수 없고, 재료·분량의 출처 표시는 없다.
- 영양 성분을 "영상 정보를 바탕으로 추정"해서 보여 준다.
- 영상 길이에 따라 이용권이 차감되고, 이미 만들어진 레시피는 무료로 볼 수 있다. 같은 영상은 한 번 만든 결과를 공유하는 것으로 보인다.

### Flavorish

- 공개 changelog에 음성 전사와 과거 GPT-4o-mini 사용이 언급되어 있다. 현재 Instagram 처리 모델이나 수집 업체를 확정하는 근거는 아니다.
- 레시피 화면의 단계는 번호, 체크, 텍스트로만 구성되고 영상 시각이나 영상 플레이어 연결은 없다.
- 영상 외에도 웹사이트, 텍스트, 이미지에서 레시피를 가져올 수 있다.
- 다른 사람의 레시피를 저장하면 내 사본이 만들어진다.
- 로그인 후 실제 영상 가져오기는 관찰하지 않았다.

### ReciMe

- 공식 도움말에 따르면 캡션·설명 → 오디오 → 원본 레시피 웹사이트 순으로 레시피를 찾는다. 원본 사이트를 찾는 구체적 방법은 미확인이다.
- 공개 레시피 페이지의 단계는 텍스트뿐이고 영상 시각은 없다.
- 재료는 원문 텍스트와 정리된 수량·단위를 함께 다룬다.
- 다른 사람의 레시피를 저장하면 기본 비공개 사본이 생기고, 원본이 바뀌거나 지워져도 영향을 받지 않는다(도움말).
- 무료 사용자는 가져오기 횟수가 제한된다.

### CookingGuru

- Shorts 형식 링크를 받는다. 일반 YouTube `watch?v=` 링크는 거절됐다.
- Shorts 한 편 변환에 약 16초 걸렸다(1건 관찰).
- 결과는 재료(품목·양·단위)와 번호 붙은 단계 텍스트다. 단계에 영상 시각은 없고, 원본 영상은 "View on YouTube" 외부 링크로만 연결된다.
- 앱 안내에 "소리가 없는 영상도 된다"고 적혀 있다. 공식 Instagram 소개도 화면 글자·내레이션·캡션 등을 분석한다고 주장한다. 실제 OCR·영상 모델과 실행 품질은 검증하지 않았다.
- 편집하면 원본 위에 내 수정이 덧씌워지고, 언어별로 따로 저장되며, 되돌릴 수 있다. 저장은 사본이 아니라 북마크다.
- 접근할 수 없는 영상은 실패 안내가 나온다.

## Instagram 구현 조사

### 공식 자료에서 확인한 범위

**네 서비스가 Instagram 링크를 지원한다고 안내하는 것과, 우리가 같은 방식으로 영상·음성을 확보할 수 있다는 것은 별개다.** 공식 자료만으로 실제 영상 주소를 얻는 수집 업체·다운로더·라이브러리는 특정하지 못했다. 공유 메뉴로 URL을 전달하는 것, 임베드로 재생하는 것, 분석용 원본을 확보하는 것을 구분한다.

| 서비스 | 공식 설명 | 아직 확인되지 않은 부분 |
|---|---|---|
| Flavorish | 공개 게시물·릴스를 공유해 가져오기. 설명에 전체 레시피가 있어야 정확하며 부족하면 요리명·해시태그 등으로 빈 내용을 채운다고 안내. 변경 이력에 음성 전사 수정 언급 | Instagram 원문·영상 확보 방법, 현재 전사·생성 모델, 릴스별 처리 우선순위 |
| ReciMe | 캡션 → 영상 음성 → 원본 레시피 웹사이트 순으로 탐색한다고 안내 | 캡션·영상·음성 수집 방법과 사용 모델 |
| 해먹으리 | 공지에서 Instagram 재생은 oEmbed라고 설명. 개인정보처리방침에 Google AI로 영상·이미지 파일 등을 전달한다고 명시 | 일반 릴스의 분석용 원본 확보 방법, 구체적 AI 모델 |
| CookingGuru | iOS 공유 확장이 URL을 전달하고 URL·메타데이터를 서버에서 처리한다고 명시. 영상·화면 글자·음성·캡션 분석을 안내 | 미디어 수집 업체·도구와 실제 처리 방식·품질 |

### 해석할 때 주의할 점

- **Flavorish:** 부족한 원문을 AI로 채운 결과와 원문에서 추출한 분량은 다르다. 우리는 근거 없는 분량을 미확인으로 남긴다. 과거 변경 이력의 모델명이 현재 Instagram 모델을 확정하지는 않는다. [공식 도움말](https://www.flavorish.ai/blog/help-center-feature-related) · [변경 이력](https://www.flavorish.ai/changelog)
- **ReciMe:** 캡션·음성·원본 사이트의 활용 순서는 공개됐지만 이를 수집하는 구체적 도구는 공개되지 않았다. 비공개·로그인·구독으로 제한된 콘텐츠는 가져올 수 없다고 안내한다. [Instagram 안내](https://recime.app/help/en/articles/11659005-import-from-instagram) · [실패 안내](https://www.recime.app/help/en/articles/14773584-why-didn-t-my-recipe-import-correctly)
- **해먹으리:** 2025-10-02 공지의 oEmbed는 재생 방식이며 영상 다운로드 방법이 아니다. 제작자에게 영상을 직접 받아 개선하겠다는 내용은 당시 계획으로 완료 여부는 미확인이다. Google AI 전달은 확보한 콘텐츠의 후단 분석 설명이고, Meta 연동 목적은 제작자 인증·프로필 연결이다. [공식 공지](https://slashpage.com/hemogry) · [개인정보처리방침](https://www.hemogry.com/privacy-en)
- **CookingGuru:** URL 전달은 영상 파일이 공유 확장에서 직접 넘어온다는 뜻이 아니다. 화면·음성 분석을 지원한다는 설명과 실제 엔진·성공률 검증을 구분한다. [개인정보처리방침](https://cooking.guru/privacy-policy) · [Instagram 소개](https://cooking.guru/instagram-recipe-converter)

### 우리 설계에 반영할 것

아래는 경쟁사의 비공개 구현을 알아냈다는 주장이 아니라 우리 설계 제안이다.

- 플랫폼별 수집 → 공통 입력 → 필요 시 시간 있는 음성 전사·OCR → 근거 묶음 → 구조화·검증으로 나눈다. 특정 경쟁사 서버를 우리 수집기로 호출하지 않는다.
- 캡션만 확보하면 설명 근거로 표시하고 영상 분석이라고 부르지 않는다. 시각 없는 텍스트에는 시각을 지어내지 않는다.
- 영상 URL 반환과 실제 접근·디코딩 성공을 구분한다. 수집 성공률과 레시피 추출 정확도를 따로 측정한다.
- 공개·사용 권한이 있는 개발용 릴스의 수집 후보를 검증한 뒤 지원 범위를 정한다. 상세 기준은 [개발 계획](dev-plan.md#instagram-수집-검증과-지원-결정)을 따른다.

## 관찰에서 정한 우리 우선순위

관찰한 화면에서는 네 서비스 모두 재료·분량별 출처 표시를 확인하지 못했다. 단계와 영상 시각 연결은 해먹으리의 YouTube 레시피에서 확인했다. 작은 표본의 관찰이므로 서비스 전체에 기능이 없다고 단정하지 않는다. **이 관찰이 곧 우리 MVP에 근거 표시를 넣어야 한다는 결론은 아니다.** 이번 MVP는 확인·수정·저장 흐름과 추출 품질에 집중한다.

| 관찰·검증 과제 | 우리 대응 |
|---|---|
| 재료·분량의 정확성 | 근거 종류·원문·시각은 내부 보관하고 분량을 검증. 항목별 출처·원문·시각은 화면에 표시하지 않음 |
| "약간·적당량"과 미확인 분량 | 근거에서 확인된 원문은 유지하고, 미확인·검토 필요·충돌 분량은 화면에서 비움. 내부 상태는 구분해 보존 |
| 플랫폼별 확보 범위 | 캡션만 사용하면 결과 전체에 한 번 "설명 기반" 안내 |
| 정확도 확인 | 고정 평가셋으로 기본 버전·개선 버전 비교. 별도 비교 세트에서 경쟁사 결과와 비교 |
| 수정과 품질의 연결 | 수정 전/후를 항목별로 보관하고 검토 후 학습 후보로 사용 |

항목별 근거 UI·시각 이동·신뢰도 요약은 MVP에서 제외한다. 근거 표시가 재확인 부담을 줄인다는 가설은 이번 MVP의 검증 대상에서 제외하고, 수정 항목 수·확인부터 저장까지의 시간·저장 완료 여부를 사용성 지표로 삼는다. 영상 재확인 횟수는 참고 지표로만 기록한다.

## 참고할 만한 사용자 경험

- 처리 중에 화면을 떠나도 되고, 레시피북에 "만드는 중" 카드가 보이는 흐름 (해먹으리)
- 같은 영상은 한 번만 만들고 결과를 공유 (해먹으리, ReciMe, CookingGuru)
- 외부 재생이 막힌 영상은 원본 앱으로 보내기 (해먹으리)
- 원본은 그대로 두고 내 수정만 덧씌우며 되돌리기 가능 (CookingGuru)
- 원문 텍스트와 정리된 수량을 함께 보관 (ReciMe)
- 요리 영상이 아니거나 열 수 없는 영상은 이유를 구분해 안내 (공통)

## 비교 실험 계획

같은 영상을 각 서비스에 일반 사용자로 넣고 **화면에 보이는 결과만** 기록한다. 우리 평가셋과 같은 라벨링 가이드로 정답을 만든 뒤 같은 지표로 채점한다. 평가셋과는 별도의 "비교 세트"로 관리한다.

- 영상 구성: 레시피가 **말로만** 나오는 영상, **화면 자막으로만** 나오는 영상, **캡션(설명)에만** 있는 영상, 세 가지가 섞인 영상
- 기록: 재료·분량 결과 캡처, 처리 시간, 실패 여부
- 지표: 재료 재현율·정밀도, 분량 정확도, 영상에 없는 분량 수
- 주의: 표본이 작으므로 "이 영상들에서는"이라는 범위를 붙여 발표한다.
- Instagram 수집 검증 세트는 경쟁 서비스 비교 세트·고정 평가셋과 분리한다. 캡션만 있는 영상, 음성에만 레시피가 있는 영상, 화면 글자 중심 영상, 혼합 영상을 구분한다. 캡션 확보·실제 미디어 접근·시간 있는 전사 확보 여부를 먼저 기록하고 추출 결과를 채점한다.
