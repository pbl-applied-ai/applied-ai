# 정답 레시피 라벨링 가이드 v0.4

수정일: 2026-11-13
변경(v0.4): 출처마다 분량이 다르면 숫자 분량이 "some"·"조금" 같은 말보다 우선(11/12 수빈 결정). 숫자끼리는 기존 순서. 11/13 #54 리뷰(선규): "한 꼬집"·"하나"·"반 개" 같은 한국어 수사도 숫자로 침, "설탕 대신 물엿 1큰술"처럼 그 재료를 쓰라는 문장의 숫자도 씀.
변경(v0.3): 영어 영상 정답 규칙 추가(7번, 영어 평가셋 v1.0-en용). 11/12: "some" 확정, 크기 표현은 분량 대신 name_raw, 같은 재료는 부분마다 따로.
변경(v0.2, KAN-52): 정답에 쓰지 않는 필드에 `amount_estimate` 추가(6번).
변경(v0.2): 분량 출처 우선순위를 고정 댓글 > 음성 > 설명으로 정함, 화면 글자는 순위에서 빼고 메모에 남김(#3 G). 화면 글자에만 분량이 있으면 `unconfirmed`. 분량이 나오는 출처에 고정 댓글 추가.
변경(v0.2, KAN-9): 스키마 v0.2에 맞춤. 재료·단계에 항목 id(아래 6번), 고정 댓글 근거 `comment-N`. v0.1로 만든 정답은 `python scripts/migrate_v01_v02.py <폴더...>`로 바꾼 뒤 `validate.py`로 검사한다.

정답 레시피(`recipe.json`)를 만들 때 지키는 규칙. 형식은 `schemas/recipe.schema.json`, 입력은 같은 폴더의 `bundle.json`이다.
규칙이 애매한 사례가 나오면 이 문서에 사례를 추가하고 PR로 합의한다. 라벨러마다 판단이 다르면 평가 점수가 의미를 잃는다.

## 작업 순서

1. 강한 모델로 초안 `recipe.json`을 만든다.
2. **영상을 처음부터 끝까지 직접 보면서** 초안을 고친다. 초안을 믿고 넘기지 않는다.
3. `python scripts/validate.py <폴더>`로 검사한다.
4. 다른 팀원 1명이 교차 확인한다.

## 1. 분량 (`amount_raw`, `amount_status`)

| 상황 | 처리 |
|---|---|
| 음성·설명·고정 댓글에 분량이 나옴 | `amount_raw`에 **나온 그대로** 적고 `confirmed` |
| 화면 글자에만 분량이 나옴 | `amount_raw: null`, `unconfirmed`. 화면 값은 후보 기록 표 메모 열에 남긴다(아래 "화면 글자") |
| 재료는 나오지만 분량이 안 나옴 | `amount_raw: null`, `unconfirmed` |
| 화면으로 짐작은 되지만 말·글로 안 나옴 | `unconfirmed`. 눈대중으로 채우지 않는다 |
| "적당히", "취향껏", "조금" | 원문 그대로 `confirmed` (영상이 준 정보가 그것뿐) |
| 출처마다 분량이 다름 | **숫자 분량이 있으면 숫자를 쓰고**, 숫자끼리는 **고정 댓글 > 음성 > 설명** 순으로 택한다. 화면 글자는 순위에 넣지 않는다(아래). 고르지 않은 출처의 구간도 `evidence`에 넣는다 |

- **출처 우선순위(#3 G, 11/3 합의):** 작성자가 직접 쓰고 고정한 댓글이 가장 정확하고, 설명란은 다른 영상과 같은 문구일 때가 있어 마지막에 둔다. "1T"와 "1큰술"처럼 표기만 달라도 출처가 다르면 충돌로 보고 같은 순서로 고른다.
- **숫자가 말보다 우선(v0.4, 11/12):** 한 출처는 "조금"·"some"·"a splash"처럼 말로만 하고 다른 출처에 숫자(단위 포함)가 있으면, 순위와 상관없이 숫자를 쓴다. 예: 음성 "설탕 조금" + 설명 "설탕 2작은술" → "2작은술". 영상이 준 가장 정확한 정보를 정답으로 삼기 위해서다. 숫자는 "2", "two", "½", "half a cup", "1 handful"처럼 수가 들어간 분량을 말한다. 화면 글자의 숫자는 여기에도 쓰지 않는다.
  - 한국어 수사도 숫자다: "한 꼬집", "하나", "두 개", "반 개", "한 숟가락". "살짝"·"조금"·"약간"·"적당히"·"넉넉히"는 숫자가 아니다. 예: 음성 "소금 살짝" + 설명 "소금 2꼬집" → "2꼬집".
  - "설탕 대신 물엿 1큰술"처럼 그 재료를 넣으라는 문장의 숫자도 쓴다. 예: 음성 "물엿을 조금" + 설명 "설탕 대신 물엿 1큰술" → 물엿 "1큰술".
- **화면 글자:** bundle에 화면 글자 구간이 없으면 근거로 쓸 수 없으므로 순위에서 빼고, `confirmed`의 근거로도 쓰지 않는다(`confirmed`는 근거 구간이 1개 이상 필요하다). 화면에만 분량이 있으면 위 표대로 `unconfirmed`. 화면 분량이 bundle 쪽 분량과 다르면 정답은 bundle 쪽 출처로 쓰고, 후보 기록 표의 메모 열에 "화면은 2T"처럼 남긴다(정답 파일에는 메모 칸이 없다). OCR을 붙인 뒤 정답을 다시 볼 때 쓴다.
- 단위를 바꾸지 않는다. "1T" → "1T", "한 큰술" → "한 큰술". 정규화는 6단계 코드가 한다.
- 숫자 표기도 원문 그대로 둔다("2~3큰술", "1/2개").

## 2. 재료 이름 (`name`, `name_raw`)

- `name`은 일반적인 표준 이름: "기름" → "식용유", "파" → "대파"(쪽파가 확실하지 않으면).
- 영상 표기가 `name`과 다를 때만 `name_raw`에 원문을 적는다.
- 브랜드명은 빼고 재료만: "○○ 굴소스" → "굴소스".
- 하나로 쓰인 재료는 하나로 둔다: "다진 마늘"은 "마늘"로 쪼개지 않는다.
- 물은 분량이나 조리에 의미가 있을 때만 재료로 넣는다.
- 장식·선택 재료는 `optional: true`.

## 3. 근거 (`evidence`)

- 재료와 단계마다 근거가 된 segment id를 모두 적는다.
- `confirmed` 분량에는 **그 분량이 나온 segment**가 반드시 포함돼야 한다.
- bundle에 근거가 없는 재료(영상에서 보이기만 함)는 넣되 `evidence: []`, 분량은 `unconfirmed`. 이런 사례는 PR에 표시한다. 1~4단계가 놓친 정보라 수빈에게 중요한 신호다.

## 4. 조리 순서 (`steps`)

- 한 단계에 한 동작 묶음. 영상의 컷이 아니라 사용자가 따라 하는 단위로 나눈다.
- 문장은 "~한다." 체로 짧게. 분량은 재료 목록에 있으니 단계에서 반복하지 않아도 된다.
- `order`는 1부터 빈틈없이.

## 5. 데이터 분할

- 분할 단위는 **영상(`video_id`)**. 같은 영상이 학습과 평가에 같이 들어가면 안 된다.
- 평가셋 폴더는 고정 후 수정하지 않는다. 평가 결과를 보고 평가셋 정답을 고치는 것도 금지(정답 오류 발견 시 팀 합의 후 버전을 올린다).

## 6. 항목 id·정답에 쓰지 않는 필드 (스키마 v0.2)

- 재료는 `ing-1`, `ing-2`…, 단계는 `step-1`, `step-2`… 순서대로 붙인다. 한 레시피 안에서 겹치면 안 된다.
- 고정 댓글 근거는 `comment-0`처럼 적는다. 댓글에는 시각이 없다.
- 정답에는 `partial`, `edited`, `user_entered`, `amount_estimate`를 쓰지 않는다. `partial`은 파이프라인이 한쪽만 찾은 결과에만 붙고, `edited`·`user_entered`는 사용자 레시피(`schemas/user_recipe.schema.json`) 전용이다. `amount_estimate`는 파이프라인이 영상에 없는 분량에 붙이는 AI 추정값(KAN-52)이라 정답에 넣지 않고, 평가도 이 칸을 보지 않는다.

## 7. 영어 영상 (영어 평가셋 v1.0-en)

- **번역하지 않는다.** 재료 이름·분량·단계 모두 영상 언어(영어)로 적는다. 파이프라인도 영상 언어로 레시피를 쓴다.
- 분량은 1번처럼 나온 그대로: "2 tbsp" → "2 tbsp", "a cup of" → "a cup", "half a teaspoon" → "half a teaspoon", "1/2 cup" → "1/2 cup". 단위·숫자를 바꾸지 않는다. 지금 평가 스크립트(`scripts/evaluate.py`)는 단위를 정규화하지 않고 글자로 비교하므로, 원문과 한 글자라도 다르면 틀린 것으로 센다.
- "a pinch", "to taste", "a splash", "a handful", "some", "a little"은 한국어의 "적당히"·"조금"처럼 원문 그대로 `confirmed`(11/12 수빈 결정). "some oil and butter"처럼 두 재료에 걸리면 둘 다 "some". 단, 다른 출처에 숫자가 있으면 숫자를 쓴다(1번 "숫자가 말보다 우선").
- **크기 표현은 분량에 넣지 않는다**(11/12 수빈 결정): "1 large garlic clove" → `amount_raw: "1"`, `name: "garlic"`, `name_raw: "large garlic clove"`. "2 mini cucumbers"도 `"2"`. 단위("2 cups", "3 cloves")는 분량에 남긴다.
- `name`은 흔히 쓰는 영어 이름(소문자): "EVOO" → `olive oil`(`name_raw: "EVOO"`).
- **같은 재료가 부분마다 나오면 따로 적는다**(11/12 수빈 결정): 양념·소스·드레싱처럼 나뉜 레시피의 "black pepper 1 tsp"(양념)·"black pepper 2 tsp"(드레싱)은 두 줄로 둔다. 합치지 않는다. 평가 스크립트가 같은 이름 여러 줄을 짝짓는지는 선규가 확인한다.
- 미국·영국 표기가 섞이면(cilantro / coriander) 영상 표기를 따른다.
- 단계 문장은 짧은 명령형: "Boil the pasta for 8 minutes."
- 2번 브랜드·하나로 쓰인 재료 규칙은 같다: "Kewpie mayo" → `mayonnaise`, "minced garlic"은 쪼개지 않는다.
