# pipeline

YouTube 요리 영상 링크를 받아 자막과 설명란을 가져오고, LLM(사용자 본인 키)으로 재료·단계·팁을 추출한다. 모든 항목은 근거 세그먼트 ID에 연결되고, 시각은 코드가 근거에서 계산한다.

- 런타임: Node.js 20 이상, 외부 의존성 없음 (ESM, `"type": "module"`)
- 현재 프롬프트 버전: `recipe-extract-v6` (`src/schema.mjs`의 `PROMPT_VERSION`)
- 기본 모델: `gpt-4.1` (`src/llm.mjs`의 `DEFAULT_MODELS.openai`)
- 테스트: `npm test` (LLM·네트워크 호출 없음)

## 실행 방법

```bash
cd pipeline
npm test                                                     # 단위 테스트 (LLM·네트워크 호출 없음)

# 아래는 LLM을 호출한다(유료). 키는 환경 변수로만 넘기고 출력하거나 파일에 남기지 않는다.
node src/cli.mjs <youtube-url>                               # 자막 → LLM → 결과 출력
node src/cli.mjs <youtube-url> --captions-only --out x.transcript.json     # 자막만 저장 (LLM 호출 없음)
node src/cli.mjs <youtube-url> --transcript x.transcript.json --out result.json

# LLM 호출 없이 저장된 모델 출력으로 후처리만 실행
node src/cli.mjs --transcript test/fixtures/sample-gochujang-bowl.transcript.json \
  --llm-output test/fixtures/sample-gochujang-bowl.llm.json

# 모델 비교·반복 실행 (결과는 compare/<프롬프트 버전>/<영상 ID>/에 저장, 커밋하지 않음)
node scripts/compare-models.mjs <transcript.json> gpt-4.1 gpt-5.5
node scripts/repeat-model.mjs <transcript.json> gpt-4.1 3
```

환경 변수:
- `OPENAI_API_KEY` 또는 `ANTHROPIC_API_KEY`
- `LLM_PROVIDER` (`openai` | `anthropic`, 기본: 설정된 키 쪽)
- `LLM_MODEL` (기본 모델 대신 쓸 모델)

`compare/`, `dev-candidates/`, `out/`, `*.transcript.json`(테스트 fixture 제외)은 `.gitignore` 대상이다. 실제 영상의 자막·실행 결과는 레포에 올리지 않는다.

## 구조와 데이터 흐름

```
YouTube URL
  └─ youtube.mjs   innertube player API(ANDROID → IOS 클라이언트)로 자막 트랙 URL을 얻고 timedtext XML을 파싱
      └─ segments.mjs  자막 → S01.. 세그먼트(kind=speech, 시각 있음)
                       설명란 → 줄마다 D01.. (kind=description, 시각 없음, URL·해시태그 줄 제외)
          └─ renderForPrompt  "[S07 00:12] 텍스트" / "[D03 설명] 텍스트"
              └─ llm.mjs   OpenAI strict json_schema 또는 Anthropic 강제 tool use
                  └─ resolve.mjs  근거 검증, 시각 계산, 분량 상태, 중복·도구 제거, 요약
                      └─ pipeline.mjs  watch_url 추가, meta(model, prompt_version, usage, latency_ms)
                          └─ print.mjs / cli.mjs  사람이 읽는 출력
```

**핵심 원칙: LLM은 시각을 쓰지 않는다.**
- LLM은 근거 세그먼트 ID만 인용하고, 코드가 인용한 세그먼트 중 가장 이른 시작 시각을 `start_ms`로 쓴다.
- 존재하지 않는 ID는 버리고 경고를 남긴다.
- 순서가 어긋난 단계는 `out_of_order`, 근거가 없는 단계는 `missing`으로 표시한다.

## 파일별 설명

| 파일 | 역할 |
|---|---|
| `src/youtube.mjs` | `parseVideoId`(watch/shorts/youtu.be/embed/live/ID), `watchUrl(id, sec)`(Shorts는 시크가 안 돼서 watch URL로 변환), `parseCaptionXml`(timedtext와 srv3), `fetchTranscript` |
| `src/segments.mjs` | `normalizeSegments`, `descriptionSegments`, `renderForPrompt`, `formatClock` |
| `src/schema.mjs` | `PROMPT_VERSION`, `RECIPE_SCHEMA`(OpenAI strict용: 모든 속성 required, `additionalProperties:false`), `SYSTEM_PROMPT`, `buildUserPrompt` |
| `src/llm.mjs` | `resolveProvider(env)`, `callOpenAI`(추론 모델이 temperature를 거부하면 빼고 재시도), `callAnthropic`, `extractRecipe` |
| `src/ingredients.mjs` | `parseAmount`: "2스푼", "1~2큰술", "한 개 반", "½ tsp", "약간"을 `{quantity, quantity2, unit, qualitative}`로 파싱. 검증·비교용이고 화면에는 항상 원문을 보여 준다 |
| `src/resolve.mjs` | 결정론 후처리 전부 (아래 참고) |
| `src/pipeline.mjs` | `loadSource`, `runPipeline` |
| `src/print.mjs` | 출력 포맷: 요약 줄, 출처별 분량, 상태 표시 |
| `src/cli.mjs` | CLI 옵션: `--out`, `--transcript`, `--llm-output`, `--lang`(기본 `ko,en`), `--captions-only`, `--json` |
| `scripts/compare-models.mjs` | 같은 자막으로 여러 모델 실행. 결과는 `compare/<버전>/<영상ID>/<모델>.json` |
| `scripts/repeat-model.mjs` | 같은 모델을 N번 실행해 실행 간 편차 확인. 결과는 `.../repeat/` |
| `test/pipeline.test.mjs` | 단위 테스트 (`node --test`). LLM 호출은 `fetch`를 모킹한다 |
| `test/fixtures/sample-gochujang-bowl.*.json` | 테스트용으로 직접 쓴 가짜 자막·설명과 기준 LLM 출력. 실제 영상 자막이 아니다 |

## 결정론 규칙 (`src/resolve.mjs`)

LLM 출력을 그대로 믿지 않고, 코드가 아래 순서로 검증한다.

1. **도구 제거:** 이름이 도구 단어로만 이뤄진 항목을 뺀다(예: "뚝배기", "뚝배기 뚜껑"). "팬케이크 가루"는 남는다. 목록은 `EQUIPMENT`.
2. **대안 재료 병합:** 인접한 두 재료의 손질법이 같고, 인용한 근거에 "A(이)나/또는/혹은 B"가 있으면 "A 또는 B" 하나로 합친다.
3. **분량 검증:** 출처마다 분량 항목을 하나씩 둔다(`amounts[]`).
   - 유효한 근거가 없으면 그 분량 항목을 버린다.
   - 인용한 텍스트에 분량 문구가 없거나(공백 무시), 숫자만 있으면("1.5") 확인 필요로 표시한다.
   - 상태: `not_in_video`(분량 없음), `conflict`(분량끼리 숫자가 다름. 단위가 없으면 어떤 단위와도 호환, 스푼=숟가락=큰술 같은 단위 계열은 같게 봄, 단위 변환은 하지 않음), `confirmed`(검토가 필요 없는 분량이 하나라도 있음), `needs_review`(그 외).
4. **중복 의심 경고:** 이름이 서로 포함 관계이고 같은 근거를 인용하면 경고만 남긴다. 근거가 다르면 경고하지 않는다("마늘"과 "다진마늘"은 따로일 수 있다).
5. **팁 중복 단계 제거:** 팁과 근거를 공유하고 문장 유사도(글자 bigram Dice)가 0.5 이상인 단계는 뺀다.
6. **시각 계산:** `start_ms`는 인용한 세그먼트 중 가장 이른 시각, `end_ms`는 다음 시각 있는 단계의 시작(마지막 단계는 마지막 말 세그먼트의 끝). 순서가 어긋나면 `out_of_order`, 근거가 없으면 `missing`.
7. **문자열 "null" 정리:** 모델이 `"null"`, `"none"`, `"n/a"` 문자열을 넣으면 null로 처리한다.
8. **상태:** `not_a_recipe`(레시피 아님), `insufficient`(재료도 단계도 없음), `ok`.

## 출력 구조

`runPipeline()`의 반환값(축약, 값은 구조 설명용 가짜 예시):

```json
{
  "source": { "platform": "youtube", "videoId": "<영상 ID>", "title": "...", "author": "...", "caption": { "language": "ko", "autoGenerated": true } },
  "evidence": [
    { "id": "S03", "kind": "speech", "startMs": 4440, "endMs": 9080, "text": "달군 팬에 기름 살짝만 붓고 마늘은" },
    { "id": "D01", "kind": "description", "startMs": null, "endMs": null, "text": "..." }
  ],
  "recipe": {
    "status": "ok",
    "title": "고추장 목살덮밥",
    "servings_text": null,
    "summary": { "ingredients": 13, "amounts_confirmed": 2, "amounts_needs_review": 0, "amounts_conflict": 0, "steps": 9, "steps_timed": 9 },
    "ingredients": [
      {
        "id": "ing_01", "sort_order": 0, "name": "기름", "preparation": null, "is_group_header": false,
        "amount_text": "살짝만", "amount_status": "confirmed",
        "amounts": [
          { "text": "살짝만", "sources": ["speech"], "verbatim": true, "unitless": false, "needs_review": false,
            "parsed": { "quantity": null, "quantity2": null, "unit": null, "qualitative": false },
            "evidence": [{ "segment_id": "S03", "kind": "speech", "start_ms": 4440, "text": "..." }] }
        ],
        "start_ms": 4440, "evidence": ["..."], "watch_url": "https://www.youtube.com/watch?v=<영상 ID>&t=4s"
      }
    ],
    "steps": [
      { "id": "step_01", "sort_order": 0, "text": "...", "is_group_header": false,
        "start_ms": 4440, "end_ms": 9080, "timing": "ok", "evidence": ["..."], "watch_url": "..." }
    ],
    "tips": [{ "id": "tip_01", "text": "...", "start_ms": 13599, "evidence": ["..."], "watch_url": "..." }],
    "warnings": []
  },
  "meta": { "model": "openai:gpt-4.1", "prompt_version": "recipe-extract-v6", "usage": { "...": "..." }, "latency_ms": 5300, "generated_at": "..." }

```

- `id`(`ing_01`, `step_01`, `tip_01`)는 사용자 레시피로 복사할 때 유지할 안정 ID 용도다.
- 화면 요약 문구 예: "재료 12개 중 7개 분량을 영상에서 확인 (확인 필요 3개, 불일치 2개) · 단계 9개 중 9개 시각 연결"

## 프롬프트 버전 이력

프롬프트를 바꾸면 `PROMPT_VERSION`을 올리고, 개발용 영상으로 이전 버전과 회귀를 비교한다.

| 버전 | 바꾼 것 | 이유 (관찰된 문제) |
|---|---|---|
| v1 | 기본 프롬프트. 근거 ID 인용, 시각은 코드가 계산 | 첫 구현 |
| v2 | 분량 원문 그대로 + 분량 근거, 없으면 null(지어내기 금지), `not_a_recipe`, 팁 분리, 설명란 줄 단위 근거, 보수적 자막 교정, 다른 요리 예시 | 계획 문서 요구사항. 비슷한 소리의 다른 음식으로 잘못 교정, 팁이 단계로 들어감, 늦은 인용 |
| v3 | "A 또는 B"는 한 항목, 팁을 단계로 반복 금지, 재료명 표준 철자 교정, 같은 대상 연속 동작은 한 단계로 | 대안 재료가 두 항목으로 분리, 재료명 오타 방치, 단계를 지나치게 잘게 나눔 |
| v4 | 분량을 출처별 `amounts[]`로 변경. 말과 설명란 분량이 다르면 둘 다 넣는다. 단위 추가 금지 | 말로 한 분량("약간")을 버리고 설명란의 단위 없는 숫자만 쓰는 경우 |
| v5 | 도구는 재료가 아님, 교정한 이름만 남김, "생략가능"은 분량이 아님 | 도구를 재료로 넣음, 교정 전후 이름이 둘 다 남음 |
| v6 | 대안 분량·다른 인분 분량은 팁으로, "다/전부"는 분량이 아님 | v4 규칙이 너무 넓게 적용돼 선택 사항 분량을 분량에 넣고 불일치로 표시 |

코드 쪽 변경: 팁 중복 단계 제거와 대안 병합(v3), 문자열 "null" 처리(v3 이후), 출처별 분량·불일치·확인 필요(v4), 중복 경고(v5), 도구 제거(v6).

## 알려진 한계

- 자막 수집이 비공식 경로(innertube player API)라 약관 검토가 필요하다. 프로덕션에서는 공식 경로나 STT 대안을 검토해야 한다.
- 재생 불가 영상과 자막이 없는 영상은 처리하지 못한다(STT 경로 없음).
- 개발용 영상이 적어 모든 판단이 작은 표본에서 나왔다.
- 테스트의 기준 LLM 출력은 직접 만든 것이고 사람 라벨이 아니다.
- 화면 자막(OCR)과 고정 댓글은 아직 근거로 쓰지 않는다.
- 단위 계열 비교가 단순하다. "1t"(티스푼)와 "반스푼"은 불일치로 나온다. 단위 변환을 하지 않기로 했으므로 의도된 동작이다.
- YouTube만 지원한다.
- 출력은 아직 팀 계약 스키마(`schemas/recipe.schema.json`) 형식이 아니다. 내보내기는 다음 PR.
